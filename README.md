# LibreSign Coverage

The source code for **this publishing website** is in this repository:
[the GitHub Actions publisher](.github/workflows/pages.yml),
[Octocov configuration](.octocov.yml), and the
[theme/navigation layer](site-theme/). The site at
[libresign.github.io/coverage](https://libresign.github.io/coverage/)
contains **generated HTML**, not a checkout of this repository. PHP coverage
refers to the [LibreSign application source](https://github.com/LibreSign/libresign).

Static code coverage reports for repositories owned by [LibreSign](https://github.com/LibreSign).

The public site is **https://libresign.github.io/coverage/** (temporary GitHub Pages URL). The project uses upstream [octocov](https://github.com/k1LoW/octocov) central mode to render the repository index and badges, and the existing PHPUnit HTML report to display line-by-line coverage.

## Data flow

1. The LibreSign CI runs PHPUnit once, generating Clover and the native HTML.
2. The same workflow runs the upstream octocov Action, producing native octocov metrics.
3. The CI publishes the outputs as a GitHub Release asset snapshot in this repository using a GitHub App restricted to `contents:write`, then requests a Pages refresh using `repository_dispatch`.
4. The Pages workflow downloads the snapshot using its own scoped `GITHUB_TOKEN`, verifies the published checksums, runs upstream octocov central mode against `local://reports`, and deploys the original PHPUnit HTML.
5. Nothing generated by CI is committed; no unsigned commits, custom coverage analyzer, extra PHPUnit runs or persistent server are required.

The `coverage-latest` release contains the current snapshot and its source commit metadata. During initial homologation it contains **real data from PR #9387**, explicitly marked as preview and not as the main-branch baseline. Once the source PR is merged, normal updates automatically replace it.

The separate [historical Coveralls archive](https://github.com/LibreSign/coverage/releases/tag/coveralls-archive-2026-11-07) preserves 3,735 historic build metadata records and per-file summaries for one build, not complete historic line-hit records. We do not fabricate such records or import them into octocov's native history model.

## Repository organization

The root Pages index lists LibreSign repositories with published data. Each repository's detailed HTML resides under its short name, e.g. `/libresign/`. Projects in other GitHub organizations do not belong in this repository.

The current source reporter is `LibreSign/libresign/.github/workflows/phpunit-sqlite.yml`. Add more LibreSign repositories by publishing compatible native octocov metrics and HTML into the same snapshot convention; do not duplicate the coverage parser or create a standalone coverage service.

## Maintenance and security

- The Pages job requires read access only to its own repository releases.
- A narrowly scoped GitHub App with `contents:write` will update the release snapshots, not commit to Git.
- Keep `central.push` disabled; all source commits require DCO and signed commits.
- Coveralls remains active during validation; do not remove it before comparing coverage and replacing historic reports/badges.
- The custom DNS name is deliberately not configured yet.

## Theme and source navigation

The static site has an accessible light/dark theme toggle, initially following
the operating system setting and remembering an explicit preference for
subsequent pages. The source links lead to this publisher and the LibreSign
application; PHP source-line pages also link to the matching source file at
the **exact commit** recorded in the coverage snapshot.

This is a small navigation layer over the original Octocov and PHPUnit
outputs. The upstream coverage data and rendered line-level reports remain
unchanged in their release assets; the theme is inserted only into the
published copies. Run the local checks with
`python3 -m unittest discover -s tests -v`.
